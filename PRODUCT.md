# 紫璃文件夹 / Violet Folders

The primary application is a Windows x64 folder shelf built with Electron, React, TypeScript, Vite, and rdev/liquid-glass-react. It watches Windows File Explorer file-system locations and keeps independent purple glass rows near the top-left edge of the desktop.

The core loop is open a folder → recognize its name and parent path → click to return. Identical paths share one row. Pinning changes a temporary row into a persistent shortcut that survives Explorer closure and app restart. Unpinned paths disappear after their last matching Explorer window closes or navigates away. A full-path tooltip supports long names.

The transparent, frameless shelf stays above ordinary desktop applications. Its header folds the folder list, supports dragging, and offers settings plus visible exit. Chinese and English UI, a tray recovery path, and Ctrl+Alt+F support frequent use. Start at sign-in is optional and off by default.

Version 1.2 uses liquid-glass-react's SVG displacement, RGB chromatic aberration, and edge highlights inside Electron's Chromium renderer. The Liquid glass effect menu entry opens controls for Standard, Polar, Prominent, or experimental Shader mode; displacement, blur, saturation, aberration, elasticity, radius, and violet tint; over-light darkening; and desktop sampling. Clear, Frosted, and Refractive presets and a full Reset support quick changes. Changes apply immediately and persist automatically. The current native app places the panel below the header with a fixed position and a maximum width of 340px. Opening it reserves a fixed window width independent of the current elasticity, preventing the controls from shifting during slider adjustments. The glass surfaces retain their dynamic elastic travel space.

Desktop refraction uses DXGI Desktop Duplication without a WGC capture border, followed by D3D11 shared textures, Electron `sharedTexture`, `VideoFrame`, and a local canvas for each glass surface. The separate pointer is never composited. Frames that cannot be confirmed free of an embedded software pointer are discarded, retaining the latest clean image. All surfaces share one frame source; each canvas samples only its transformed area plus `P = ceil(3 * blurPx + maxRGBDisplacement / 2 + 3)` padding. The SVG filter region expands with that padding while its displacement map stays on the capsule. This keeps blur and RGB displacement supplied with nearby pixels without allocating a full-desktop canvas per row. Complementary filter masks are added to preserve opacity and prevent a second desktop image from leaking through.

Capture requires Windows 10 build 19041 or later for native self-exclusion, with Windows 11 still awaiting verification. Before capture starts, the app directly sets and verifies its own window's capture-exclusion flag and uses `DwmFlush` to settle desktop composition. Transient startup failures retry without requiring manual interaction. Capture targets 30fps; actual frame rate requires device verification. GPU textures are shared across processes without per-frame JPEG encoding or pixel-array IPC. Frames stay in local memory and are never recorded, saved, or uploaded. The desktop refraction switch stops capture and releases textures. Unavailable capture uses transparent glass with a stable dark veil and light ink, and exposes its status in the controls. Browser preview uses a detailed fixture scene and never captures the desktop.

Text and icons adapt to the background using fifteen luminance samples every 250ms, with saturation applied before measuring and tint and over-light darkening included in the decision. Hysteresis prevents repeated switches near the threshold. Text shadows are removed, and tint and reflection layers sit above the optical background and below sharp content.

Each 72px capsule occupies an 82px slot with a transparent gap. The adjustable radius is capped by the capsule height. Elasticity defaults to 0.15, with horizontal space of `8 + ceil(100 * elasticity)` and vertical space of `10 + ceil(22 * elasticity)` pixels reserved for stretching and translation. This keeps the transformed surface from being cut off by list edges. A light, adjustable violet overlay replaces the old dense fill, leaving background details available for refraction. A solid, high-contrast settings menu and optical panel preserve readability. Empty and collapsed states show only the compact header unless a settings panel is open.

Windows 10 22H2 x64 with a 2560×1440 desktop is the verified development environment. DXGI self-exclusion passed a 24-frame red/green/red pixel comparison, including the first valid frame of every phase. Native capture, three-frame backpressure, click-through exclusion, release after close, and packaged automatic startup were verified separately. Static desktops reuse the last GPU frame for local elastic redraws; new desktop frames depend on actual changes. Performance varies with hardware, glass parameters, and load. Windows 11 compatibility requires target-machine verification. Windows 11 also has specific limitations around background Explorer tabs exposed through Shell COM. Secure desktop, UAC, lockscreens, exclusive fullscreen, virtual Shell pages, and third-party file managers are outside the normal operation guarantee.

Preferences, including the optical settings, are local to the current user at %APPDATA%\Violet Folders\settings.json, shared by development and packaged builds through the fixed application name. Existing settings gain default optical values while preserving pins, language, collapse state, and bounds. Runtime behavior does not upload paths, file contents, or desktop samples. Source and unsigned portable EXE / ZIP packages can be distributed through the private GitHub repository. npm scripts and scripts/build.ps1 build the primary Electron app; the renderer builds to dist-renderer and packages to release. Source builds require Visual Studio C++ x64 tools and a Windows SDK with C++/WinRT. `npm run build:native` builds the capture module and runs automatically for development and distribution, including CI packaging. Portable packages include the native module and runtime; users need no compiler or SDK.

The earlier WPF implementation remains under src/VioletFolders with its existing .NET tests and scripts/build-legacy-wpf.ps1. It is preserved source, not the current primary application or distribution path.
